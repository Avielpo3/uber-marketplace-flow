Uber Marketplace Flow

The switch is disabled, and the existing NewOrderMakeline call makes mp-uber subscribe to the order in tracker-service. Nothing polls. An Uber Eats order is always delivered by us, either by a store driver or, when none is free in time, by a daas-uber courier. Uber Eats only receives order statuses and courier locations. mp-uber sends both the same way for every order and never knows which kind of carrier delivered it.

Switch off

mp-uber keeps /order/switch behind switchToUberDeliveryEnabled (default false), so it answers 404 and nothing calls switch-fulfillment-type. The order is registered by NewOrderMakeline and stays a restaurant delivery (BYOC).

		}

	case "returned":
		return providers.CouldNotDeliver, providers.Unassigned
